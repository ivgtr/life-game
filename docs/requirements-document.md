# ライフゲーム観賞・生態系ビューア Webサイト開発依頼プロンプト

あなたはフロントエンドに強い Web エンジニア / クリエイティブコーダーです。  
以下の要件に基づき、「ライフゲーム（Conway's Game of Life）」を眺めて楽しみ、そこに“生態系”や“世界観”を感じて癒やされる Web サイトを設計・実装してください。

---

## 1. ゴール / コンセプト

- ライフゲームのセルの動きを「生態系」や「小さな宇宙」を眺めるように鑑賞できるサイト。
- ユーザーが積極的に操作しなくても、ただ開いておくだけでボーッと眺めていられる “癒やし系スクリーンセーバー”的な体験。
- 雑多な UI ではなく、シンプルで没入感のあるデザイン。  
  → 「観る」「感じる」が主役で、「いじる」はサブ。

---

## 2. 想定ユーザー / 利用シーン

- PC のサブモニターに常時表示して眺めていたい人。
- 作業の合間にふと視線を預けて気分転換したい人。
- ライフゲームやセルオートマトンが好きな人（技術寄りユーザーも想定）。
- 就寝前にスマホで眺めて落ち着きたいユーザー。

---

## 3. 画面構成（ざっくり）

### 3-1. メイン画面

- ほぼ全画面キャンバスでライフゲームを表示。
- 画面の四隅 or 下部に控えめな操作パネル（透明度高め、マウスオーバーで濃くなる）。

### 3-2. UI 要素（例）

- 再生 / 一時停止ボタン。
- 速度調整スライダー（例：0.25x / 0.5x / 1x / 2x / 4x）。
- 「シーンプリセット」セレクトボックス（後述：生態系テーマ）。
- 「Zen モード」トグル（UI 完全非表示で全画面鑑賞）。
- ランダムシード生成ボタン。
- スナップショット保存 / お気に入り登録ボタン（可能であれば）。

---

## 4. コア機能要件

### 4-1. ライフゲームの基本

- Conway's Game of Life のルールでセルオートマトンを実装。
- グリッドサイズ：
  - PC：横 80〜150、縦 50〜100 程度（画面解像度に応じてスケーリング）。
  - スマホ：パフォーマンスに応じて自動調整。
- トーラス（端同士がループ）での実装を基本とし、オプションで切り替えられると尚良い。

### 4-2. 観賞モード

- ページ表示と同時に自動でシミュレーション開始。
- 一切操作しなくても、ランダムシードやプリセットシーンを自動で切り替えながら永遠に動き続ける「おまかせ観賞モード」。
  - 例：数分〜10分ごとに次のシーンへフェード遷移。
- シーン切り替え時にはフェードイン・フェードアウトやズームイン/アウトなど、穏やかなトランジションを入れる。

### 4-3. シーンプリセット（“生態系”テーマ）

以下のような「世界観」を持つプリセットを複数用意すること：

- 例）
  - **Forest**：緑系の色、ゆっくり成長するような印象のパターン。
  - **Ocean**：青系グラデーション、波のように広がるパターン。
  - **Nebula**：宇宙っぽい紫〜ピンクグラデーション、星雲のようなノイズから始まる。
  - **City Lights**：暗い背景にカラフルな点がチカチカする印象。
  - **Desert**：黄〜オレンジ系、静かに崩れていくパターン。

**実装イメージ：**

- 各プリセットは以下を持つ。
  - 初期配置生成アルゴリズム（ランダムに偏りを持たせる、ノイズ、グライダー群、ラインなど）。
  - カラーパレット（背景色、死細胞色、生細胞色、フェードアウト色）。
  - シミュレーション速度やズーム感などのパラメータ。
- プリセットはユーザーが選択可能＋おまかせモード時にはランダムローテーション。

### 4-4. セルの描画表現

- 単純な四角形でもよいが、「癒やし」重視で以下のような工夫が望ましい：
  - 角を少し丸める。
  - 生→死、死→生の遷移時に短いフェードアニメーション。
  - 生存世代数に応じて色が変化（長寿なセルほど色が変わるなど）。
  - 遠景・近景のような疑似パララックス表現（任意）。

---

## 5. ユニーク機能アイデア（優先度：中〜低）

### 5-1. 「生態系メモ」オーバーレイ

- シーンごとに、画面の片隅に 1〜2 行のテキストをふわっと表示。
  - 例：「この世界では、群れを成して移動する“グライダー群”が優勢です。」
  - 内容はランダム生成の短い詩的テキストでも可。
- ユーザーがオン/オフ切り替え可能にする。

### 5-2. 「観察ノート」機能（あれば嬉しい）

- ユーザーがお気に入りの状態を「撮影」して、簡単なメモを添えて保存。
- ローカルストレージ保存で構わない（サーバーサイド実装は任意）。
- ギャラリー画面で過去のスナップショットを一覧で眺められる。

### 5-3. 穏やかなサウンド（実装できれば）

- プリセットごとに、ループ可能な環境音/BGM を割り当て。
  - Forest → 小鳥のさえずり＋風。
  - Ocean → 波音。
  - Nebula → アンビエントなシンセ音。
- ミュートボタン必須。初期状態の挙動（音あり / なし）は開発者側で提案してよい。

### 5-4. 「Slow Cinema」的時間制御

- 通常の 1 ステップ単位よりもさらに遅くして、1 ステップごとに静止画のように切り替わるモード。
- 例：3 秒に 1 ステップしか進まないモード → 観察に適した“超スローライフ”モード。

---

## 6. 非機能要件

### 6-1. パフォーマンス

- PC で全画面表示しても快適に動作すること（理想は 60fps 前後。多少下回っても体験が破綻しなければ可）。
- スマホではフレームレートを自動で落とすなど負荷軽減策を取る。
- ウィンドウ非アクティブ時は自動でシミュレーションを一時停止する、または更新間隔を大幅に落とす。

### 6-2. レスポンシブ

- PC・タブレット・スマホで表示崩れしないレイアウト。
- 操作 UI はモバイルでもタップしやすいサイズ。

### 6-3. アクセシビリティ

- コントラスト比に配慮（特に文字要素）。
- キーボード操作でも基本操作（再生/停止、速度変更、プリセット切り替え）ができると望ましい。
- 色覚多様性に配慮したカラーテーマを少なくとも 1 つ用意（例：モノクロームテーマ）。
