## 出力フォーマット（タスクの書き方）

基本的には Markdown で、開発者がそのままコピペして使える形にしてください。

### 1. 一覧サマリー

まずはタスク全体像を俯瞰できるように、カテゴリ別に整理してください：

- 例）

```md
## タスク全体サマリー

- [ ] 01\_要件読み込み・セットアップ
- [ ] 02\_ライフゲームコアロジック実装
- [ ] 03_PixiJS 描画レイヤー実装
- [ ] 04_UI（コントロールパネル・プリセット選択など）
- [ ] 05\_観賞モード・Zen モード実装
- [ ] 06\_パフォーマンス調整・スマホ対応
- [ ] 07_GitHub Pages + Actions デプロイフロー構築
- [ ] 08\_テスト・品質担保
```

### 2. タスク詳細（GitHub Issue 化できる粒度）

各タスクは、以下の情報を含めてください：

- **ID**：`TASK-001` のような識別子（任意で良いが一意）
- **タイトル**：簡潔な要約
- **種別**：`feature | chore | refactor | test | docs` など
- **優先度**：`High / Medium / Low`（または P1 / P2 / P3）
- **概要**：何を実現するタスクか 2〜4 行程度で説明
- **詳細 TODO**：チェックボックス形式で 3〜8 個程度のサブタスク
- **受け入れ条件（Acceptance Criteria）**：完了判定の具体的な条件
- **関連仕様**：どのプロンプトのどのセクションに対応しているか（分かる範囲で）

例：

```md
### TASK-002: ライフゲームコアロジック（LifeEngine）の実装

- 種別: feature
- 優先度: High

#### 概要

Conway's Game of Life のルールに基づくコアロジックを、描画レイヤーに依存しない純粋な TypeScript モジュールとして実装する。

#### TODO

- [ ] グリッド・セル状態を表現する型定義 (`CellState`, `Grid` など) を作成
- [ ] 初期状態生成関数（ランダム・プリセット初期化など）の実装
- [ ] 次世代の計算ロジック（近傍カウント・ルール適用）の実装
- [ ] トーラス（端ループ）対応の有無を切り替えられるようにする
- [ ] シミュレーション設定用のインターフェース（速度・サイズなど）を定義
- [ ] ユニットテスト（基本パターン・安定構造・振動子・グライダーなど）

#### 受け入れ条件

- 単体テストで代表的なパターン（ブロック・ブリンカー・グライダー等）の挙動が期待どおりになる
- 描画層からはグリッドと設定を渡せば「次の世代のグリッド」が取得できる構造になっている
- 技術選定プロンプトの「ライフゲームコアロジック設計」に沿った API 形になっている

#### 関連仕様

- 要件定義編: 「4. コア機能要件 → 4-1. ライフゲームの基本」
- 技術選定編: 「2. ライフゲームロジックと Svelte / PixiJS の分離設計 → 2-1. ライフゲームコアロジック」
```

## 優先順位づけの方針

- 特に指示がなければ、次の順番で優先度をつけてください：
  1. **MVP として必要な体験のコア**
     - ライフゲームロジック
     - PixiJS 描画
     - 基本的な観賞モード（再生/停止・速度変更・ランダムシード）

  2. **初期リリースで欲しい体験強化要素**
     - プリセット（Forest / Ocean / Nebula など）
     - Zen モード・UI 最小構成
     - レスポンシブ対応

  3. **拡張 / 演出 / ユニーク機能**
     - 生態系メモ
     - 観察ノート
     - サウンド

  4. **テスト・ドキュメント・リファイン**
     - テスト整備
     - README / 開発ドキュメント
     - パフォーマンスチューニング
